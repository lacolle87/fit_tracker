# Fit Tracker

Локальный трекер питания, веса и активности на DuckDB: CLI + веб-дашборд, без облаков и аккаунтов. Все данные остаются в одном локальном файле `fit.duckdb`.

## Возможности

- **Учёт питания**: продукты и готовые блюда, калории и БЖУ на приём и за день, дневные и недельные цели.
- **Готовые блюда**: сохраняешь массу и БЖУ всей партии — дальше логируешь порциями.
- **Вес и состав тела**: замеры веса, %жира, %мышц, недельный тренд скорости снижения.
- **Активность**: шаги и тренировки (тип, длительность, интенсивность).
- **БАДы и лекарства**: отдельный справочник и журнал приёма, не смешиваются с калориями.
- **Дашборд**: калории/БЖУ против целей, список приёмов пищи, графики веса и скорости снижения, недельные средние.
- **Штрихкоды**: поиск продукта по штрихкоду через OpenFoodFacts (`barcode.py`).

## Быстрый старт

Требуется Python 3.10+.

```bash
python -m pip install -r requirements.txt
python fit_tracker.py init
python fit_tracker.py log "яйцо 120; рис вареный 150; овощи свежие 200"
python fit_tracker.py today
```

Вес указывается в граммах, строка парсится по разделителям `;`. Повторный ввод в течение дня просто добавляется — `today` пересчитает итог.

## Основные команды

| Команда | Назначение |
|---|---|
| `init` | создать базу и схему |
| `log "название 200; ..."` | записать приём пищи |
| `today [--date]` | итог дня: калории, Б/Ж/У, приёмы пищи |
| `add-food name kcal protein fat carbs` | добавить продукт (на 100 г) |
| `add-dish name grams kcal p f c` + `log-dish name 0.5` | сохранить блюдо и логировать порции |
| `log-measurement weight fat muscle` | замер веса и состава тела |
| `log-steps 10000` / `log-workout "силовая" 60` | активность |
| `add-supplement` / `log-supplement` | БАДы и лекарства |
| `set-targets 1770 105 70 180` | цели по калориям и БЖУ |
| `db_query.py` | read-only SQL-хелпер по базе (`foods`, `meals`, `sql <file>`) |

## Запуск UI (дашборд)

Дашборд — это локальный веб-сервер + одна HTML-страница. Данные читает напрямую из `fit.duckdb`, ничего никуда не отправляет.

**Вариант 1 — вручную:**

```bash
python dashboard.py
```

Затем открой `http://127.0.0.1:8765`.

**Вариант 2 — с рабочего стола:**

Запусти `start_dashboard.bat` (или создай на него ярлык). Он поднимает сервер и сам открывает страницу. Когда закрываешь вкладку браузера — сервер завершается автоматически.

**Что внутри:**

- калории дня и лимит, факт/цель по белкам/жирам/углеводам (полоски и донат);
- приёмы пищи по категориям с удалением записей;
- шаги, тренировки за 30 дней, последний замер (вес / %жира / %мышц);
- график веса с целевой линией и недельная скорость снижения (кг/нед);
- средние за период (7 или 30 дней — переключатель), дневные графики БЖУ/калорий/шагов;
- поиск продуктов по штрихкоду (EAN) с камерой телефона.

Целевой вес и цель недельного темпа задаются в `dashboard.html` (константы в секции графиков веса).

## Хранение данных

Всё лежит в одном файле `fit.duckdb` (DuckDB, включён в `requirements.txt`). Схема — в `db/schema.sql`, пример стартовых данных — в `db/seed.sql`. База в git не попадает (см. `.gitignore`) — данные остаются только у тебя.

## Разработка

```bash
python -m flake8 .
python -m py_compile fit_tracker.py db.py nutrition.py
python -m unittest discover -s tests
```

Перед коммитом прогоняй flake8 и py_compile. Git используется локально; сетевые операции — только по явному решению владельца репозитория.

## Принципы

- Локальность: никаких облаков, аккаунтов и телеметрии — данные только на твоей машине.
- Прозрачность: простая схема БД, читаемый CLI, статичный HTML-дашборд.
- Осторожность: цели по питанию корректируются по многодневной динамике веса, а не по одному замеру; автоматических «пересчётов рациона от тренировок» нет.
